# M32 W5 paired pilot

The [frozen protocol](M32_PAIRED_PILOT.json) evaluates two separate tasks: the original spinning-top objective and mass minimization under a 90% full-body inertia floor. Each A/B/C/D arm uses the same W4 diagnostic coefficient hint and native seed-0 sequence of up to eight spinning-top starts, in the same coordinate frame and native order, on the same recorded hardware and CPU-thread budget. Three repetitions measure timing variability. A refused start or unsuccessful run is retained with its elapsed time. A continuous-objective diagnostic gave a negative multiplier near −16.54 at the hint; the production discrete result is unmeasured. The unchanged native generator and its version are pinned in the protocol. All diagnostics, restarts and corrections consume the same pair of caps. For the separate mass-continuation panel every arm uses the shared diagnostic and native sequence for the 95% threshold, then initializes the 90% threshold from its own independently verified 95% solution. Report the whole pair against the same total 600 s / 120-request cap, including the first solve and cache cost; also report incremental cost for the second point. A missing verified 95% state leaves continuation unavailable. The primary learning comparison freezes both models with zero adaptation; a separately admitted two-step run must charge its support queries and time.

For each arm and repetition across the entire start schedule, stop at 600 seconds or 120 exact geometry requests, whichever comes first. Cold runs include geometry setup. The warm panel reuses only geometry preprocessing/encoding and charges its one-time cost separately. For each task independently, compare time only after independent whole-body acceptance and an objective no larger than the paired verified A value plus 0.001×max(1, |A|). For equal-budget mass, report the best independently feasible candidate before both caps. No candidate means a failed row. This pilot covers one shared initial-condition schedule on M32. Broader claims require independent starts and held-out object families.

The [readiness receipt](M32_PILOT_READINESS.json) was produced from the pinned W2 manifest and W4 witness. The teacher manifest admits zero train/validation/test rows. M32, its rotations, all trajectories and related measurements stay together; the existing W5 family and geometry-digest leakage checks must pass before claiming any cross-geometry result. The witness is an analytic reference, not a fitted label, a measured runtime or a strict solver terminal. Original-evaluator compatibility and independent end-to-end acceptance remain required.
