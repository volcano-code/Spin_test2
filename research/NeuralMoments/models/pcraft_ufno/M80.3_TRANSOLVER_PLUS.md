M80.3 is a Spin-specific reimplementation/adaptation of the physical slicing mechanism. It does not copy the upstream source file, CFD checkpoints, data pipeline, distributed all-reduce code or Gumbel sampling implementation. It should be described as **Transolver++-style mass-aware physical-state slicing**, not as an unmodified Transolver++ port.

## Architecture

P-CRAFT remains the global spectral geometry encoder. M72 native RLE intervals are encoded once into interval features \(h_i\). Optional GNO may first update local features. The Transolver-style branch then performs:

1. Multi-head projection \(h_i\to x_{i,h}\).
2. Per-interval/head learned slice logits and a learned positive temperature.
3. Deterministic soft assignment across slices.
4. Native-mass-weighted physical slice pooling.
5. Q/K/V scaled-dot-product attention over the small physical-slice axis.
6. Deslicing the updated slice states back to every native interval using the same learned assignment.
7. Residual projection and feed-forward update.
8. The existing native-mass-weighted global reduction and M72 moment response head.

For interval mass \(m_i\), normalized \(\bar m_i=m_i/\sum_jm_j\), learned logits \(a_{ihs}\), and temperature \(\tau_{ih}\), the deterministic assignment is

\[
A_{ihs}=\operatorname{softmax}_{s}\left(a_{ihs}/\tau_{ih}\right).
\]

The physical slice mass and token are

\[
\mu_{hs}=\sum_i\bar m_i A_{ihs},\qquad
z_{hs}=\frac{\sum_i\bar m_i A_{ihs}x_{ih}}{\mu_{hs}+\epsilon}.
\]

Attention is applied only over \(S\) slices per head:

\[
\tilde z_h=\operatorname{SDPA}(W_Qz_h,W_Kz_h,W_Vz_h).
\]

The desliced interval feature is

\[
x'_{ih}=x_{ih}+W_O\left(\sum_s A_{ihs}\tilde z_{hs}\right),
\]

followed by a residual feed-forward block.

The cost scales with \(NHS D + HS^2D\), rather than constructing an \(N\times N\) attention matrix. All native intervals contribute to slice construction and receive the updated state.

## Deliberate deviations from upstream

- Deterministic softmax is used instead of stochastic Gumbel-softmax. This preserves reproducibility for repeated geometry queries and derivative calculations.
- Native interval mass is included in slice pooling. This is a Spin-specific physical measure, not the unweighted CFD point aggregation.
- The module is geometry-encoding-time and query-independent, so one encoded geometry can serve many quadric coefficient queries. The query-dependent moment head remains downstream.
- No distributed all-reduce is needed for the current single-GPU 5090D workflow.
- The number of slices is deliberately modest (16 for Large, 32 for XL); attention is only across these learned physical states.

## Diagnostics

Preflight/training receipts report:
- assignment row normalization error;
- mass-weighted slice-mass sum error;
- effective number of used physical slices;
- assignment entropy;
- learned temperature min/mean/max;
- GNO graph build/cache/edge statistics when GNO is enabled.

A collapse to one or two effective slices, unstable temperature, high memory cost or no held-out Jacobian/solver improvement is a reason not to promote the module.

## Required validation

1. CPU: assignment normalization, mass normalization, finite gradients, moment scale/complement invariants, AD Jacobian, second-order backward.
2. GPU: paired Large/Large-Transolver and Large-GNO/Large-GNO-Transolver preflights on the same largest M72 geometry.
3. Short pilot: same data, split, seed, optimizer, batch, chunk and update count for all four variants.
4. XL: only after the Large variants pass; compare the four XL variants.
5. Promote Transolver only if it improves held-out Jacobian tail or downstream solver outcomes at acceptable wall time and memory.

Preflight is not evidence of learning quality. No Transolver GPU run or Newton end-to-end speedup is claimed until the user executes and returns the local receipts.
